## 一、⚠️ 鼓件编码必须映射（对接时最容易错的地方）

协议 v1 的鼓件编码与 `voice_render` 的 voice 类型**不是同一套编号**，直接对接会导致
"敲底鼓响军鼓"。映射表如下，已写进 `demo_ensemble.m` 的 `DRUM2VOICE`：

| 协议鼓件编码 | 含义 | voice 类型 | 说明 |
|---|---|---|---|
| 0 | 底鼓 | **1** | kick：150→55Hz 扫频 + click |
| 1 | 军鼓 | **2** | snare：180/200Hz 双模态 + 5~9kHz 响弦 |
| 2 | 闭镲 | **3** | hihat：7~10kHz 噪声 + 金属共振 |
| 3 | 开镲 | **3** | 与闭镲同音色，靠音长（byte10）区分 |
| 4 | 桶鼓 | **1** | 暂用 kick 音色，改参数需改 `init_engine.m` |

```matlab
DRUM2VOICE = [1 2 3 3 1];   % 按 code+1 索引
```

## 二、力度位宽转换

协议里力度是 **uint16（0–65535）**，`voice_render` 里 `vel` 是 **Q15（0–32767）**。

- 打包（B → 总线）：`vel16 = vel7bit × 512`（队长的示例帧 32768 = vel 64，与此一致）
- 解包（总线 → 引擎）：`vel_q15 = vel16 >> 1`

## 三、帧格式确认（已与队长文件互验）

小端，12 字节：

```
[0]=AA [1]=55
[2]=bit7:6 乐器ID(00钢琴/01鼓/10笛/11吉他) bit4 事件(0触发/1松开) bit3:0 通道
[3]=保留
[4:5]=时间戳 uint16 单位 5ms
[6:7]=音符/鼓件 int16
[8:9]=力度 uint16
[10]=音长 uint8 单位 0.05s（0=按住直到松开）
[11]=前 11 字节异或校验
```

## 四、互操作性验证结果（已跑）

用 `lib/protocol_unpack.m` 解析队长的 `sim/teamA/test_frames.bin`：

| 帧 | 时间戳 | 乐器 | 编码 | 力度 | 音长 | 校验 |
|---|---|---|---|---|---|---|
| 1 | 0 ms | 0 钢琴 | 60 (C4) | 32768 | 0.50 s | ✅ 通过 |
| 2 | 500 ms | 0 钢琴 | 64 (E4) | 32768 | 0.50 s | ✅ 通过 |
| 3 | 1000 ms | 1 鼓 | 0 (底鼓) | 32768 | 0.10 s | ✅ 通过 |

**结论：队长的打包器与 B 的解包器完全互认，校验算法一致。**

## 五、端到端合奏 demo

`demo_ensemble.m` 走完整链路：
曲谱 → `protocol_pack` 打包 → 写 `audio/ensemble_frames.bin` → `protocol_unpack` 解包校验
→ 32 声部定点引擎渲染 → `audio/ensemble_demo.wav` + `fig/ensemble_demo.png`

实测：20 帧（钢琴 8 + 鼓 12），**峰值 27853，削波 0 个样本**。

> 这个 demo 用的是 B 定点引擎里的钢琴（type 4），其参数已与队长口径对齐
> （3 谐波 1:0.35:0.12、tau 1.2/0.6/0.3s、起音 10ms）。
> 队长 `piano_synth.m` 是浮点版，用于听感参考；两者参数一致，
> 若要完全对齐可让 A 导出其包络表 `env_lut` 再替换 `piano_env.m`。

## 六、给 C 的提醒（串口播放器）

- 帧长严格 12 字节，按 12 对齐切分，别按行/按分隔符读
- 校验失败直接丢帧，**不要**尝试重传（音频实时流，重传比丢帧更糟）
- 按时间戳调度，`音长=0` 的帧要等对应的"松开"帧（byte2 bit4=1）才停
